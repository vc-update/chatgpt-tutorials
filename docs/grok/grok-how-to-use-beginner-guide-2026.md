## 第一步：确认入口和账号边界

普通网页先看 [grok.com](https://grok.com/)，产品说明看 [x.ai/grok](https://x.ai/grok)，开发者接口看 [docs.x.ai](https://docs.x.ai/)。X 内的 Grok 使用 X 账号和 X 页面环境，不能因为品牌名称相同就把所有历史记录、权限和功能直接等同。

登录前完成三项检查：

1. 地址栏是否是你主动打开的可信域名；
2. 页面是否清楚说明服务主体和账号方式；
3. 是否要求提供密码、验证码、恢复码或 API Key 给第三方人员。

如果你选择中文多模型平台，<a href="https://gptcat.cc" target="_blank" rel="nofollow sponsored noreferrer">GPTCat</a>适合先比较多个模型和当前页面提供的多媒体能力；<a href="https://snakegpt.vip" target="_blank" rel="nofollow sponsored noreferrer">SnakeGPT</a>适合中文问答、翻译和总结；<a href="https://www.zeogpt.com/register?ref=MRNWDKC3" target="_blank" rel="nofollow sponsored noreferrer">ZeoGPT</a>更偏代码、Codex和开发者工作流。它们都是独立第三方服务，不是 Grok 官方入口。

## 第二步：完成第一次中文对话

第一轮不要用含糊的“帮我写得好一点”。可以按“目标—背景—材料—格式—限制”五部分写：

```text
你是一名中文技术编辑。
目标：把下面的产品说明整理成一篇给新手看的操作清单。
读者：第一次接触这项工具的普通用户。
输出：
1. 先给一句话结论；
2. 再用编号列出操作步骤；
3. 用表格列出可能遇到的错误和排查动作；
4. 最后列出原文没有说明的待确认信息。
限制：不要添加材料中没有的价格、型号、承诺或官方关系。
材料：
{粘贴公开文本}
```

拿到结果后检查四件事：是否回答了目标、是否遵守格式、是否遗漏材料中的限制、是否把推测写成事实。发现问题时用具体指令迭代，例如“只改表格第二列，不要改变原文数字”。

## 第三步：掌握连续追问

Grok类对话工具的效率来自逐轮收窄，而不是一次Prompt塞入所有要求。一个实用的追问顺序是：

| 轮次 | 追问示例 | 目的 |
|:---|:---|:---|
| 第1轮 | 请先提取材料中的事实 | 建立事实清单 |
| 第2轮 | 把事实按时间、人物和动作分组 | 结构化整理 |
| 第3轮 | 标出没有证据支持的句子 | 识别推测 |
| 第4轮 | 按目标读者改写成短说明 | 生成可读初稿 |
| 第5轮 | 保留数字和链接，逐项列出待核验内容 | 发布前复核 |

每一轮只改变一个主要目标，更容易发现错误来源。长对话出现上下文偏移时，重新粘贴关键事实清单，比继续追加十几条指令更可靠。

## 第四步：用Grok处理实时信息时怎么核验

如果当前入口显示联网、搜索或实时信息功能，先把它当成“找线索”的工具，而不是自动完成事实核查。建议要求：

```text
请先列出你使用的来源、发布时间和对应结论。
把来源明确支持的内容与推断分开。
如果找不到一手来源，请标记“未核实”，不要补充确定数字。
最后告诉我哪些内容需要回到原始页面复查。
```

对新闻、政策、产品型号、会议日期、价格和安全建议，至少核对：

- 来源是否是一手页面；
- 发布时间是否晚于事件或版本变化；
- 摘要是否省略了条件和例外；
- 链接是否能打开且内容确实支持结论；
- 不同来源之间是否存在冲突。

“能联网”不等于“每句话都正确”，模型生成的链接也不自动等于真实来源。

## 第五步：文件、图片和其他工具怎么判断

只有当前账号和页面实际显示相应按钮时，才按页面说明使用附件、图片或其他工具。功能入口可能因产品、账号、地区和时间而变化，文章中的旧截图不能作为当前权限证明。

### 文件任务的低风险测试

先准备一份不含隐私的短文档，要求模型：

1. 列出文件标题、页数或可识别章节；
2. 抽取关键事实并保留原文位置；
3. 标出无法读取、模糊或缺失的部分；
4. 再生成摘要，不改变数字和限定条件。

不要直接上传客户合同、身份证件、财务报表、私钥、未公开源代码或公司内部资料。第三方平台还要单独核对数据保存、删除和训练使用规则。

### 图片任务的验收方法

如果页面提供图片理解或生成工具，先使用公开图片或非敏感草图测试。检查文字是否准确、主体是否完整、版权素材是否有使用权限，以及最终内容是否需要人工修正。不要把按钮存在理解成固定的模型版本或长期额度承诺。

## 常见错误与排查表

| 错误表现 | 可能原因 | 处理顺序 |
|:---|:---|:---|
| 无法打开网页 | 域名、网络、服务状态或脚本问题 | 核对最终域名、隐私窗口、另一浏览器 |
| 登录循环 | Cookie、系统时间或账号混用 | 清理相关站点数据并重新打开可信入口 |
| 中文输出不稳定 | Prompt未指定语言、材料混杂或上下文过长 | 明确简体中文、术语和输出格式 |
| 回答出现过时信息 | 来源时间旧、实时功能未启用或未核验 | 要求来源与日期，回到原始页面复查 |
| 文件按钮不见了 | 账号、产品入口或功能开放不同 | 以当前菜单和官方说明为准 |
| 第三方平台模型切换失败 | 路由、额度或平台功能变化 | 查看平台公告，用公开材料做最小测试 |

不要同时更换账号、浏览器、网络和平台，否则无法判断真正原因。每次只改变一个变量，并记录时间和错误原文。

## 六个实用中文Prompt

### 中文总结

```text
请用简体中文总结下面材料。
先给50字以内结论，再列5条事实。
每条事实保留原文中的数字和限定词；材料没有的信息标记为“未提及”。
```

### 翻译与术语表

```text
请把下面英文翻译成简体中文。
先列出专有名词对照表，再给完整译文。
不要擅自翻译产品名、代码、URL和参数；不确定术语请保留英文并说明。
```

### 会议纪要

```text
请从下面会议记录中提取：决定事项、待办、负责人、截止日期和待确认信息。
没有明确负责人的地方不要猜测，用“待确认”标记。
```

### 方案比较

```text
请比较方案A和方案B。
只使用我提供的材料，按目标、成本因素、风险、实施步骤和未知信息输出表格。
最后给出“选择前还需要确认”的清单，不要替我编造结论。
```

### 代码解释

```text
请先解释这段代码的输入、输出和副作用，再指出可能的边界条件。
不要直接修改代码；如果建议修改，请给出最小差异和测试用例。
```

### 内容审校

```text
请检查下面文章中的事实、数字、时间、链接和绝对化表述。
输出三列：原句、问题类型、建议核验动作。
无法确认的地方标记为“需要人工核验”，不要自行补充来源。
```

## 账号安全与发布前检查

完成任务后，发布或转发前做一次人工验收：

- 事实、数字、日期和链接是否能回到原始来源；
- 是否混入模型臆测、未经授权的个人信息或内部资料；
- 图片、文章和代码是否有使用权；
- 是否把第三方平台描述成官方服务；
- 是否需要保留对话记录或清除上传文件；
- 是否使用了独立密码，且没有暴露验证码或 API Key。

如果你的任务是代码仓库、API或命令行自动化，请进入[开发者教程栏目](/developers/)，不要把网页聊天工具的权限与本地开发代理混为一谈。需要比较不同模型的中文长文表现，可以参考 [GPT Home 的使用指南](https://gpthomechat.com/chatgpt/chatgpt-usage-guide-2026.html) 和 [Claude 中文长文与代码对比](https://claude-chinese-guide.com/blog/claude-vs-chatgpt-long-document-file-coding-chinese-writing-20260722)，再用同一份材料复测。

## 常见问题FAQ

### Grok新手最适合从什么任务开始？

从公开、短小、可核对的材料开始做摘要、改写或表格整理。先验证中文、格式和事实边界，再逐步增加多轮追问和工具任务。

### Grok怎么让回答更准确？

说明目标、背景、材料范围、输出格式和限制，并要求标出未知信息。对重要结论提供原始来源或自己复核，不要只靠“再想一遍”。

### Grok可以替代搜索引擎吗？

它可以帮助整理搜索线索，但不能替代对一手来源的阅读。实时信息要看来源、时间、上下文和是否存在冲突。

### Grok为什么会编造链接或数字？

生成式模型可能在信息不足时补全看似合理的内容。要求列出来源、缩小范围并逐项回到原始网页核对，不能把格式漂亮当成事实证明。

### Grok可以直接处理公司内部文件吗？

先遵守组织的数据政策。未经批准不要上传客户、员工、合同、财务、密钥和未公开代码；第三方平台还要核对数据保存和删除规则。

### 国内用户想用多个AI模型怎么选？

可以用同一任务比较官方网页和明确标注第三方身份的多模型平台。重点看实际模型菜单、输出质量、隐私、账号管理和退出方式，不要只看宣传星级或版本名称。
