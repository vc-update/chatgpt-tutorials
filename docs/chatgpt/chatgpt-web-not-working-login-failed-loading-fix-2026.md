## 先判断是哪一类故障

不要一上来就删除所有数据。先记录页面表现、出现时间和已经尝试的步骤，再从下表确定方向：

| 页面表现 | 更可能的方向 | 第一个测试 |
|:---|:---|:---|
| 域名根本无法打开 | 网址、网络、DNS或服务状态 | 手动输入网址并查看状态页 |
| 打开后整页白屏 | 缓存、扩展、脚本或服务异常 | 无痕窗口打开同一网址 |
| Logo后一直转圈 | 登录会话、Cookie或网络链路 | 关闭标签页后重新登录 |
| 登录按钮反复跳回 | 登录方式、Cookie或系统时间 | 使用注册时相同方式登录 |
| 对话能开但消息发不出去 | 当前服务、账号限制或会话状态 | 新建对话提交一条短文本 |
| 手机正常、电脑异常 | 电脑浏览器或本机设置 | 电脑换浏览器测试 |
| 官方页正常、第三方页异常 | 第三方平台自身问题 | 查看该平台公告或联系支持 |

### 按错误关键词快速定位

| 看到的提示或现象 | 先做什么 | 暂时不要做什么 |
|:---|:---|:---|
| `Something went wrong` 或消息发送失败 | 新建空白对话，查看状态页，再用无痕窗口发送短文本 | 不要连续重复提交相同请求 |
| `与网络有关`、连接超时或页面打不开 | 对照另一浏览器、设备和网络，检查代理、DNS与安全软件 | 不要把一次超时直接判断为账号被封 |
| 登录后白屏或一直转圈 | 关闭旧标签页，用原登录方式在无痕窗口测试 | 不要在多个页面同时反复登录 |
| 验证码循环、跳回登录页 | 检查Cookie、系统时间、自动翻译和登录域名 | 不要向陌生域名提交密码、验证码或恢复码 |
| 只有文件或图片功能失败 | 先用短文本测试，再进入对应的文件或图片排查页 | 不要把功能故障归因于整个账号不可用 |

如果报错发生在文件上传阶段，不要继续在本页兜圈子，直接进入[ChatGPT上传文件失败排查](/chatgpt/chatgpt-chinese-web-first-prompt-file-image-task-tutorial-20260724)。

## 第一步：核对网址与官方状态

### 1. 手动输入官方域名

官方ChatGPT产品入口应以 `chatgpt.com` 为准。打开后检查地址栏中的最终域名和HTTPS状态，不要因为搜索结果写着“官网”“中文版”就直接输入密码。

旧书签或旧文章可能经过跳转。跳转本身不一定有问题，但最终地址必须由你核对。需要系统辨别官网、教程站和第三方平台，可以查看[ChatGPT官网入口辨别指南](/chatgpt/chatgpt-official-url-domestic-gpt5-login-entry)。

### 2. 查看官方状态页

访问 [OpenAI Status](https://status.openai.com/) 查看是否有ChatGPT登录、会话、文件或图片相关故障。状态页没有异常也不能百分之百排除局部问题，但可以避免在官方服务故障时反复清缓存、换密码。状态页事件列表通常会把已恢复事件标记为 `resolved`，记录事件名称和时间比截取一张旧截图更可靠。

记录三个信息：

1. 故障开始的大致时间；
2. 是所有设备都失败，还是只有一个浏览器失败；
3. 账号能否完成登录，还是登录后才白屏。

## 第二步：排查浏览器与Cookie

### 先用无痕窗口做对照

在Chrome、Edge或Safari中打开无痕/隐私窗口，手动输入 `chatgpt.com` 并用原来的登录方式测试。结果有两种：

- **无痕窗口正常**：原浏览器的Cookie、缓存或扩展更可疑；
- **无痕窗口仍异常**：继续测试另一浏览器或设备，不要立即认定账号被封或密码错误。

### 暂时关闭可能冲突的扩展

优先检查以下类型：

- 广告与脚本拦截；
- 网页自动翻译；
- 隐私和Cookie拦截；
- 修改网页样式的扩展；
- 自动填充和密码管理扩展；
- 网络代理或请求改写扩展。

每次只关闭一个扩展并刷新。全部一次关掉虽然快，却无法知道真正原因，后续也容易复发。

### 只清理相关站点数据

如果无痕窗口正常，可以先清除 `chatgpt.com` 相关Cookie和站点数据，而不是删除所有网站的浏览记录。清理后通常需要重新登录，因此先确认自己记得注册时使用的是邮箱、Google还是Apple账号。

## 第三步：解决登录失败与验证循环

### 使用原来的登录方式

同一个邮箱地址通过“邮箱密码登录”和“使用Google继续”进入的账号状态可能不同。若登录后发现聊天记录为空，先退出并换回注册时的方式，不要急着重新注册。

### 检查Cookie、时间和翻译

登录页面反复刷新或验证后又返回原页时，依次检查：

1. 浏览器是否阻止必要Cookie；
2. 系统日期、时间和时区是否正确；
3. 页面是否被自动翻译扩展改写；
4. 是否在多个标签页同时重复登录；
5. 登录链接是否仍停留在官方域名体系。

验证码、恢复码和密码只应提交给对应官方登录流程。任何第三方中文平台都不应要求你的OpenAI密码、验证码、恢复码或API Key。

## 第四步：排查网络、设备与系统时间

当多个浏览器都打不开时，再检查设备和网络：

| 检查项 | 怎么做 | 判断结果 |
|:---|:---|:---|
| 另一设备 | 同一网络下用手机或另一台电脑测试 | 只有一台失败，多半是本机问题 |
| 另一网络 | 在符合当地规则和服务条款的前提下对照另一可用网络 | 只有一条网络失败，检查网络设置 |
| DNS | 先恢复为自动获取或组织批准的配置 | 手动DNS可能导致解析异常 |
| 系统时间 | 开启自动日期、时间和时区 | 时间错误会影响证书和登录验证 |
| 安全软件 | 查看是否拦截浏览器脚本或HTTPS连接 | 不要永久关闭安全防护 |
| 浏览器版本 | 更新到当前稳定版 | 旧版本可能不支持新的网页能力 |

公司、学校或公共网络可能有自己的访问策略。不要绕过组织管理规则；需要处理公司资料时，先确认允许使用的AI服务和数据范围。

## 手机与电脑的排查差异

### 手机浏览器

- 关闭“请求桌面网站”后再测试一次；
- 检查Safari或Chrome是否阻止全部Cookie；
- 暂时关闭内容拦截器和自动翻译；
- 不要在内置于社交软件的浏览器里登录重要账号；
- 从系统浏览器手动输入网址，避免被中间页面改写。

### Windows或macOS电脑

- 先用浏览器无痕窗口，不急着安装客户端；
- 检查扩展、代理、DNS和安全软件；
- 清理单个站点数据后重新登录；
- 如果网页版正常而桌面应用异常，单独检查应用版本和安装来源。

## 什么时候应该停止反复尝试

出现下面情况时，继续刷新通常没有帮助：

- 官方状态页已经确认服务故障；
- 同一错误在多个设备和网络上稳定复现；
- 页面要求在非官方域名输入OpenAI验证码；
- 登录后出现不认识的账号、邮箱或付款信息；
- 已经连续多次触发验证码或安全检查。

此时应保存错误文字和发生时间，停止输入敏感信息。官方问题等待状态恢复或按官方支持流程处理；第三方平台问题联系对应运营方。
