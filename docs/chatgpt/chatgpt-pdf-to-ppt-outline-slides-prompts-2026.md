## 第一步：检查PDF是否可读

先从PDF里复制一小段文字。如果复制结果正常，通常可以继续提取；如果无法选中文字、顺序错乱或出现乱码，可能是扫描件、字体编码或复杂版式问题。

| PDF情况 | 处理方法 | 重点检查 |
|:---|:---|:---|
| 正常文本PDF | 按章节提取文字和表格 | 页码、脚注、表格标题 |
| 扫描版PDF | 先OCR，再抽查关键页 | 数字、小数点、专有名词 |
| 双栏论文 | 分栏提取或按章节复制 | 阅读顺序、图注和引用 |
| 含大量表格 | 单独导出关键表格 | 单位、合计、同比环比 |
| 文件过长 | 保留目录、摘要、结论和相关章节 | 不要丢失上下文与版本 |
| 加密或受限PDF | 使用有权限的原文件或合法导出版本 | 不绕过访问控制 |

文件上传本身失败时，先阅读[PDF、Word、Excel上传错误排查](/chatgpt/chatgpt-chinese-web-first-prompt-file-image-task-tutorial-20260724)，不要连续提交同一个大文件。

## 第二步：明确PPT的听众与目标

同一份PDF可以被做成完全不同的PPT。开始前先写清六项信息：

1. **听众**：管理层、客户、老师、同学还是技术团队；
2. **时长**：5分钟、10分钟还是30分钟；
3. **目标**：汇报进展、申请资源、解释研究还是推动决策；
4. **必须保留**：哪些结论、数字、图表或原文引用不能省略；
5. **不能推断**：材料没有写明的内容不得补写；
6. **输出形式**：页数、语言、组织模板和是否需要讲稿。

没有这些限制，模型很容易把PDF改写成一组看似完整、实际上没有演示目标的摘要页。

## 第三步：建立带页码的证据表

不要直接要求“读完PDF后做PPT”。先让模型输出证据表：

| 编号 | 原PDF页码 | 原文事实或数据 | 可支持的PPT结论 | 状态 |
|:---|:---:|:---|:---|:---|
| E01 | 3 | 项目目标与范围 | 为什么要启动项目 | 已核对 |
| E02 | 7 | 核心指标及统计周期 | 当前表现和主要问题 | 待核对单位 |
| E03 | 12 | 方案A与方案B差异 | 推荐方案的依据 | 已核对 |
| E04 | 18 | 风险与限制 | 决策前需确认的事项 | 已核对 |

证据表有三个作用：避免模型把不同章节拼错、帮助你快速回到原页核验、让每张PPT都能回答“依据是什么”。

### 证据提取提示词

```text
请只根据我提供的PDF内容建立证据表，不要补充外部事实。

字段包括：
1. 证据编号
2. PDF原页码
3. 原文事实、数据或结论
4. 可以支持的演示观点
5. 仍需人工确认的问题

要求：
- 保留数字的单位、时间范围和统计口径；
- 无法识别的内容标记为“无法确认”；
- 不要把推测写成PDF原文结论；
- 相互矛盾的内容单独列出。
```

## 第四步：生成PPT大纲

十分钟汇报通常可以从8页结构开始，再根据内容删减：

| 页码 | 页面任务 | 推荐内容 |
|:---:|:---|:---|
| 1 | 建立主题 | 标题、对象、日期、汇报人 |
| 2 | 给出结论 | 一句话结论与三项关键发现 |
| 3 | 交代背景 | 为什么现在需要关注 |
| 4 | 展示现状 | 核心数据、趋势和差距 |
| 5 | 解释原因 | 关键因素与证据编号 |
| 6 | 提出方案 | 方案、收益、成本和依赖 |
| 7 | 说明风险 | 限制、待确认项和应对 |
| 8 | 推动行动 | 决策事项、负责人和下一步 |

论文答辩、课程分享或产品路演不必照搬这个顺序。原则是每页回答一个问题，并推动听众理解下一页。

### 页纲提示词

```text
请根据上面的证据表，为【听众】设计一份【时长】的PPT大纲。
演示目标是【希望听众理解或决定什么】。

每页输出：
- 页码
- 页面标题（直接写结论，不写空泛栏目名）
- 本页要回答的问题
- 3个以内的支撑要点
- 使用的证据编号
- 建议图表或视觉形式

只能使用证据表中的信息。没有证据的内容标记为“待确认”。
```

## 第五步：生成逐页文案与讲稿

页纲确认后，再逐页生成内容。不要一次要求模型写完几十页，否则后面的页面容易重复、失去证据约束。

### 单页文案结构

- **标题**：写结论，而不是“市场分析”“项目背景”；
- **正文**：三个以内的要点，每点尽量一行；
- **证据**：标记E01、E02等编号，方便回查；
- **视觉**：说明用柱状图、流程图、对比表还是时间线；
- **讲稿**：补充背景和过渡，不把全部讲稿塞进页面。

```text
请为第【X】页生成逐页文案。

页面结论：【已确认的页面标题】
证据编号：【E01、E03】
听众：【角色】
演讲时间：【本页预计秒数】

输出：
1. 页面标题，20字以内；
2. 最多3条页面要点；
3. 图表或视觉建议；
4. 80至120字讲稿；
5. 需要人工核对的数字、引用和推断。
```

## 两个完整使用场景

### 场景一：把行业报告做成管理层汇报

重点不是复述报告目录，而是回答：市场发生了什么、对公司有什么影响、现在要做什么。应优先提取趋势、关键数字、竞争变化、机会和风险，并把建议明确标为“基于材料的分析”或“待管理层决策”。

### 场景二：把论文做成答辩PPT

建议结构是研究问题、方法、数据、结果、讨论、限制和结论。模型可以压缩语言和整理讲稿，但引用、实验设置、样本量和统计结论必须回到论文原文核对。不得让模型补造文献或实验结果。

## 可直接复制的PDF转PPT提示词

```text
你是演示文稿编辑。请帮助我把PDF材料整理成可核对的PPT草稿。

听众：【填写】
汇报时长：【填写】
演示目标：【填写】
预计页数：【填写】
必须保留：【填写】
禁止推断：【填写】

工作顺序：
1. 判断材料是否存在无法识别、缺页或矛盾；
2. 建立带原页码的证据表；
3. 等我确认后再生成PPT大纲；
4. 每页只保留一个结论，并标注证据编号；
5. 生成逐页文案、图表建议和讲稿；
6. 最后输出事实、数字、引用和隐私复核清单。

不要补充材料中没有出现的事实。无法确定时明确写“待确认”。
```

## 最终交付前检查

- 每个数字都能回到PDF原页码；
- 标题表达结论，而不是空泛分类；
- 一页只有一个主要观点；
- 图表单位、时间、样本范围一致；
- 讲稿和页面文字没有完全重复；
- 引用、图片和字体符合使用权限；
- 内部资料已经脱敏；
- 最后一页明确下一步、负责人或讨论问题。
